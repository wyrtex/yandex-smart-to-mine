# Свой умный дом, совместимый с Яндексом

Все устройства из «Дома с Алисой» доступны в собственной системе со всеми
умениями и свойствами, со своими сценариями, историей и iOS-приложением.
Алиса при этом продолжает ими управлять.

## Что уже есть

| Часть | Что делает |
|---|---|
| **Ядро** (`smarthome/core`) | Единый реестр устройств в модели Яндекса (capabilities/properties), события об изменениях, история состояний (SQLite, 90 дней) |
| **Адаптер Яндекса** | Вход в аккаунт прямо из интерфейса (OAuth), опрос состояний каждые 10 с, команды, запуск сценариев Яндекса, автообновление токена |
| **Адаптер Zigbee2MQTT** | Устройства на своём Zigbee-стике: мгновенно и локально. Лампы, выключатели (в том числе многоканальные), датчики открытия, движения, протечки, дыма, климата, кнопки. Все сырые поля доступны как `z2m.*` |
| **Сценарии** | Триггеры по состоянию, времени и интервалу; условия (состояние, время, «не», «или»); действия: устройства, задержки, сценарии Яндекса, вложенные сценарии |
| **Веб-интерфейс + API** | Комнаты, карточки устройств, все элементы управления, графики показаний, редактор сценариев, журнал. Обновления в реальном времени через WebSocket |
| **iOS-приложение** (`ios/`) | Оболочка, которая берёт интерфейс с сервера: обновился сервер — обновилось приложение, переустанавливать не нужно. Работает по HTTP без S |

## Архитектура

```
 Дом (работает и без интернета)                              Облако
┌─────────────────────────────────────────┐
│ мини-ПК / Raspberry Pi                  │
│  smarthome: ядро, сценарии, интерфейс   │── API Яндекса ──► лампы, ТВ (Wi-Fi, только облако)
│  Mosquitto + Zigbee2MQTT + стик         │
│    └─ датчики, выключатели (локально)   │◄── VPS (NL): HTTPS-адрес для навыка Алисы,
└─────────────────────────────────────────┘    доступ к дому снаружи (следующий этап)
        ▲ iPhone: приложение «Умный дом»
```

Чтобы дом работал без интернета, ядро должно стоять **дома**: туда же
подключается Zigbee-стик. VPS остаётся для навыка Алисы (Яндексу нужен публичный
HTTPS-адрес) и для доступа к дому снаружи. Пока домашнего компьютера нет, ядро
можно запустить на VPS: Яндекс-устройства будут работать уже сейчас.

### Голос без интернета: что реально возможно

- Алиса распознаёт речь в облаке Яндекса. Без интернета некоторые станции
  со встроенным Zigbee-хабом умеют выполнять простые команды («включи свет»),
  но только для Zigbee-устройств, подключённых **напрямую к ним**. Проверьте,
  поддерживает ли это ваша модель.
- Поэтому устройства, которыми нужно управлять голосом без интернета, лучше
  оставить на хабе или станции Яндекса. Наша система видит их через облако, когда
  интернет есть. Устройства, которые нужны в своих сценариях мгновенно и без
  интернета, переносим на свой стик.
- Wi-Fi-лампы и телевизор Яндекса работают только через облако: без интернета ими
  не управляет никто, ни Алиса, ни мы.
- Полностью офлайн-голос возможен на следующем этапе: локальное распознавание
  русской речи (Vosk) на домашнем сервере с микрофоном.

## Запуск сервера

### Docker (рекомендуется)

```bash
git clone https://github.com/wyrtex/yandex-smart-to-mine && cd yandex-smart-to-mine
cp .env.example .env            # впишите YANDEX_CLIENT_ID, YANDEX_CLIENT_SECRET, SMARTHOME_PASSWORD
docker compose up -d --build    # интерфейс: http://<адрес-сервера>:8000
```

Когда появится Zigbee-стик: в `.env` укажите `MQTT_HOST=mosquitto` и
`ZIGBEE_SERIAL_PORT` (например `/dev/ttyUSB0`), затем
`docker compose --profile zigbee up -d --build`. Интерфейс Zigbee2MQTT будет на порту 8080.

### Без Docker

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -e '.[dev]'
python -m smarthome serve       # http://0.0.0.0:8000
pytest                          # тесты
```

### Вход в Яндекс

Откройте интерфейс → «Настройки» → «Войти через Яндекс», подтвердите доступ,
скопируйте код со страницы Яндекса и вставьте его в поле. Токен сохранится на
сервере и будет обновляться сам.

> Если сервер доступен из интернета, обязательно задайте `SMARTHOME_PASSWORD`.

## iOS-приложение

Сборка идёт на GitHub Actions (macOS), workflow `.github/workflows/ios.yml`.
Готовый неподписанный `SmartHome.ipa` появляется:
- в релизе **ios-latest** на странице Releases репозитория;
- в артефактах запуска workflow.

Установка: Sideloadly, AltStore или TrollStore. Они подпишут IPA вашим Apple ID;
с бесплатным Apple ID подпись нужно продлевать раз в 7 дней.

При первом запуске приложение спросит адрес сервера, например `192.168.1.10:8000`.
Позже его можно сменить в «Настройки → Адрес сервера в приложении». Весь интерфейс
грузится с сервера, поэтому переустанавливать приложение нужно только при
изменениях в папке `ios/`.

## Сценарии

Сценарий описывается в JSON и редактируется в интерфейсе (вкладка «Сценарии»).
Ключи состояний (`on_off.on`, `range.brightness`, `event.open`, `float.temperature`…)
видны в карточке каждого устройства в разделе «Ключи для сценариев».

```json
{
  "name": "Свет в прихожей при открытии двери",
  "mode": "restart",
  "triggers": [{"type": "state", "device": "Датчик двери", "key": "event.open", "to": "opened"}],
  "conditions": [{"type": "time", "after": "18:00", "before": "07:00"}],
  "actions": [
    {"type": "device", "device": "Свет в прихожей", "set": {"on_off.on": true, "range.brightness": 70}},
    {"type": "delay", "seconds": 180},
    {"type": "device", "device": "Свет в прихожей", "set": {"on_off.on": false}}
  ]
}
```

| | Варианты |
|---|---|
| Триггеры | `state` (device, key, to, from, above, below) · `time` (at `"07:30"`, days `[1..7]`) · `interval` (seconds) |
| Условия | `state` (device, key, op: eq/ne/gt/lt/ge/le/in, value) · `time` (after, before, days) · `not` / `or` (conditions) |
| Действия | `device` (device, set; `"+5"` / `"-5"` — относительное изменение) · `delay` · `yandex_scenario` · `scenario` · `log` |
| mode | `single` — не запускать повторно, пока выполняется · `restart` — перезапускать · `parallel` |

## API

| Метод | Путь | |
|---|---|---|
| GET | `/api/devices` | все устройства и комнаты |
| POST | `/api/devices/{id или имя}/action` | `{"set": {"on_off.on": true}}` или `{"actions": [...формат Яндекса]}` |
| GET | `/api/devices/{id}/history?key=&hours=24` | история состояний |
| GET/POST/DELETE | `/api/scenarios` · `/api/scenarios/{id}` | свои сценарии |
| POST | `/api/scenarios/{id}/run` · `/stop` | запуск / остановка |
| GET, POST | `/api/yandex/scenarios` · `/api/yandex/scenarios/{id}/run` | сценарии Яндекса |
| WS | `/ws` | события `state`, `devices`, `log`, `scenario` |

Авторизация: cookie после `/api/login` или заголовок `Authorization: Bearer <пароль>`.

## CLI

```bash
python -m smarthome discover            # все устройства со всеми умениями и свойствами
python -m smarthome state "Лампа"
python -m smarthome brightness "Лампа" 40
python -m smarthome scenario "Я дома"
```
